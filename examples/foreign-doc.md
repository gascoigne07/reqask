# Техническое задание: учёт товаров на складе «СкладУчёт»

Версия 0.9 от 14.10.2026. Статус: на согласовании.

## 1. Общие сведения

| Поле | Значение |
| :--- | :--- |
| Наименование | Система учёта товаров на складе «СкладУчёт» |
| Заказчик | ТОО «Северный логистический центр» |
| Площадки | Центральный склад и склад №2 |
| Смежные системы | Бухгалтерия 1С, терминалы сбора данных (ТСД) |

### 1.1 Цель

Перевести учёт прихода, расхода и перемещения товаров с бумажных журналов на электронную систему. Остаток по каждой позиции должен быть виден в момент операции, а инвентаризация должна занимать один рабочий день вместо трёх.

### 1.2 Термины

- **Позиция**: товар с одним артикулом в справочнике.
- **Ячейка**: место хранения на стеллаже с кодом вида `A-01-03`.
- **Резерв**: количество товара, закреплённое за заказом и недоступное для других операций.
- **ТСД**: терминал сбора данных со сканером штрихкода.

## 2. Роли

| Роль | Что делает |
| :--- | :--- |
| Кладовщик | Принимает и выдаёт товар, сканирует штрихкоды, проводит пересчёт |
| Старший кладовщик | Проводит накладные, утверждает перемещения между складами |
| Менеджер по закупкам | Ведёт справочник товаров, создаёт заказы поставщикам |
| Администратор | Управляет пользователями и правами |

Права ролей подробно описаны в разделе 7.3.

## 3. Функциональные требования

### 3.1 Справочник товаров

**ФТ-01.** Менеджер по закупкам создаёт позицию с полями: артикул, наименование, единица измерения, штрихкод, срок годности (если применимо).

**ФТ-02.** Артикул состоит из 8 цифр и уникален в пределах справочника.

**ФТ-03.** Для весовых товаров количество учитывается в килограммах с точностью до 0,001 кг.

**ФТ-04.** Система запрещает удалять позицию из справочника, если её остаток хотя бы на одном складе больше нуля.

### 3.2 Приход товара

**ФТ-05.** Система должна позволять создавать приходную накладную, печатать этикетки на каждую единицу товара и отправлять накладную в бухгалтерию 1С.

**ФТ-06.** Кладовщик сканирует штрихкод товара на ТСД, система находит позицию в справочнике и показывает её наименование и текущий остаток.

**ФТ-07.** После проведения накладной старшим кладовщиком остаток позиции увеличивается на принятое количество.

### 3.3 Выдача и резерв

**ФТ-08.** При создании заказа на отгрузку система резервирует товар. Резерв действует 24 часа с момента создания заказа, после чего снимается автоматически.

**ФТ-09.** Списание товара, количество которого больше доступного остатка (остаток минус резерв), отклоняется с сообщением «Недостаточно товара».

**ФТ-10.** Товары с истекающим сроком годности выделяются в списке остатков цветом.

### 3.4 Перемещение между складами

**ФТ-11.** Перемещение создаёт кладовщик склада-отправителя. Перемещение считается выполненным после того, как старший кладовщик утвердит его.

**ФТ-12.** Во время перемещения товар не входит в остаток ни одного из складов.

### 3.5 Инвентаризация

**ФТ-13.** Кладовщик пересчитывает товар в ячейке и вводит фактическое количество на ТСД.

**ФТ-14.** Если фактический остаток отличается от учётного больше чем на 5%, система создаёт акт расхождения. Если отличие меньше 5%, учётный остаток исправляется на фактический автоматически.

**ФТ-15.** Акт расхождения утверждает руководитель.

### 3.6 Отчёты и доступ

**ФТ-16.** Пользователь с ролью «Кладовщик» не видит раздел «Отчёты» в меню.

**ФТ-17.** Поиск позиции по артикулу или наименованию должен работать быстро.

**ФТ-18.** Срок хранения журнала операций: TBD, уточнить у службы безопасности.

## 4. Интеграция и данные

### 4.1 Метод API `POST /api/v1/stock/writeoff`

Метод списывает товар со склада. Вызывается с ТСД и из внешних систем.

| Поле | Тип | Обязательное | Описание |
| :--- | :--- | :--- | :--- |
| `sku` | string(8) | да | Артикул позиции |
| `warehouse_id` | integer | да | Идентификатор склада |
| `cell_code` | string | нет | Код ячейки, например `A-01-03` |
| `quantity` | integer | да | Списываемое количество |
| `reason` | string | да | Причина списания: `sale`, `damage`, `expired` |
| `user_id` | integer | да | Кто списывает |

Ответ при успехе: код 200 и тело `{"operation_id": "<uuid>", "balance": <число>}`.

### 4.2 Списание при недостатке остатка

Если на складе меньше товара, чем указано в `quantity`, метод выполняет списание, остаток уходит в минус, а операция помечается флагом `negative_balance` для последующего разбора старшим кладовщиком.

### 4.3 Обмен с 1С

Проведённые накладные выгружаются в 1С раз в сутки в 23:00 по времени Астаны.

## 5. Нефункциональные требования

**НФТ-01.** Интерфейс ТСД должен быть удобным для кладовщика.

**НФТ-02.** Система работает круглосуточно, плановые работы проводятся не чаще одного раза в месяц с предупреждением пользователей за 24 часа.

**НФТ-03.** Обмен данными между ТСД и сервером идёт только по HTTPS с TLS версии 1.2 или выше.

**НФТ-04.** Одновременно в системе работают до 60 пользователей.

## 6. Критерии приёмки

1. Позиция создаётся с артикулом из 8 цифр, повторный артикул отклоняется.
2. Приход по накладной увеличивает остаток после проведения.
3. Резерв по заказу автоматически снимается через 72 часа, если заказ не отгружен.
4. Списание сверх доступного остатка отклоняется.
5. Инвентаризация с расхождением больше 5% создаёт акт расхождения.
6. Кладовщик не видит раздел «Отчёты».
